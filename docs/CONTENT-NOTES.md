## Known problems in the reading

Key nothing to these points.

- **Thermal paste:** 3.4.6 and 3.4.7 give two different ways to apply it.
- **3.3.8, last sentence:** it reverses the rest of the section on ECC (which kind of DDR5 RAM does what). CertMaster 3.0 Q75 was skipped because it depends on that sentence.
- **2.3.4, adapters:** it lists HDMI to DVI among video adapters that "convert between signaling types," and says passive adapters work only when both ends use the same signaling. HDMI and DVI-D carry the same digital signal, so a passive adapter works. Key nothing to whether an HDMI or DVI adapter is active or passive. Messer C41 (a DVI-D video card to an HDMI projector) is held until this is settled. Quotes for c1-u02-q042 and c1-u02-q043 should come from the "like digital HDMI to analog VGA" sentence, not the line that lists HDMI to DVI.
- **3.1.11 and 3.1.12, heat sinks:** 3.1.11 describes passive and active heat sinks (active ones typically use a fan), while 3.1.12 says a heat sink is a passive cooling device that needs no electricity. No key depends on it so far.
- **5.4.10, signal strength:** "anything over -80 dBm is likely to suffer packet loss or be dropped" is backwards by the section's own rule that values closer to zero are better (it means weaker than -80 dBm). Unit 5.0 keyed nothing to the -80 dBm figure; c1-u05-q052 rests on "closer to zero is better" and "-65 dBm is a good signal".
- **NFC range, 5.4.12 and 9.1.10:** 5.4.12 says NFC "normally works at up to two inches (6 cm)"; 9.1.10 says 10 cm (about 4 inches), up to 20 cm (9 inches) for some devices. Both conversions are off (two inches is about 5 cm; 20 cm is about 8 inches). Unit 5.0 keyed nothing to an NFC distance; Unit 9.0 should do the same.
- **5.3.7, crimper:** "A crimper is used to fix a jack to a patch cord", then the same paragraph calls the part an RJ45 plug. Unit 5.0's questions say plug or connector.
- **6.2.15, IPv6 subnets:** "A /48 block allows the private network to be configured with up to 65,336 subnets." Sixteen bits of subnet ID give 65,536. Unit 6.0 keyed nothing to the number of subnets.
- **6.3.2, NACK:** it lists a TCP "negative acknowledgment (NACK) to force retransmission of a missing or damaged packet." TCP has no NACK. Unit 6.0 keyed nothing to it; the fact that TCP recovers lost packets stands on 6.2.4.
- **6.2.12 and 6.4.3, figure descriptions:** the DHCP pool in 6.2.12's figure runs from 192.168.0.100 to 192.168.1.199 (not one /24), and step 5 of 6.4.3's figure says the authoritative server "returns the name server" where it means the host's address. Key nothing to either figure.
- **6.2.14, spotting a public address:** the rule (not from a private range, does not start with zero, below 224) leaves out 127.x.y.z and 169.254.x.y, so both would pass as public. No Unit 6.0 question uses either as a choice in a public-or-private question; c1-u06-q022 uses only private, 224-and-above, and ordinary public addresses.
- **3G speeds, 6.1.8 and 9.1.7:** 6.1.8 gives about 3 Mbps (UMTS, EV-DO) and up to 42 Mbps (HSPA+); 9.1.7 gives about 7.2 Mbps. Key nothing to a 3G speed. 6.1.8 gives no 5G speed (9.1.7: up to 10 Gbps).
- **4.2.3, beep codes:** the table gives the original IBM PC's codes and says codes vary by maker. Its continuous-beep row (a memory problem) does not match commonly published lists of the original IBM PC codes, which give a power supply or system board fault. Messer A16 and PBQ C2 give two beeps with a blank screen as faulty RAM; the table gives two short beeps as a POST error shown on screen. Unit 4.0 keys no code from the table: c1-u04-q018 keys only that codes vary by maker, so the technician looks the code up.
- **4.1.8, HSM:** defines a hardware security module only as a secure USB key or thumb drive that stores keys, and never says which of the TPM and HSM creates keys or speeds up cryptography. c1-u04-q010 and the HSM card (c1-u04-f012) stay inside that definition.
- **4.1.6, Linux keys:** says keys for Fedora, openSUSE, and Ubuntu are pre-loaded in the firmware. In practice those distributions start through a shim loader that Microsoft signs. Key nothing to which keys are pre-loaded.
- **4.2.7, BCD:** says the boot sector "includes Boot Configuration Data (BCD)". BCD is a data store file on the system or EFI partition, not boot sector code. Key nothing to where BCD lives. MBR, GPT, BCD, GRUB, and LILO are not Core 1 objective terms, so Unit 4.0 has no cards for them.
- **4.2.8, memory dump:** "If you have a support contract, a memory dump is generated." Windows writes the dump either way. Key nothing to it.
- **4.2.12, "Array Failure":** the numbered paragraph labeled Array Failure describes replacing one failed disk; the array that has failed is the later "Unavailable Volume or array missing" step. Quotes for RAID questions should come from the rebuild sentence or the troubleshooting steps, not the label.
- **S.M.A.R.T.:** objective 5.2 says "Self-monitoring and Reporting Technology"; 4.2.11 says "Self-Monitoring Analysis and Reporting Technology" and also writes S.M.A.R.T and SMART. The card (c1-u04-f032) uses Self-Monitoring, Analysis, and Reporting Technology. Key nothing to the spelling. The kit's assemble script counts "S.M.A.R.T. " inside a stem as the end of a sentence, so end the sentence with it.
- **7.1.6, IMAP:** "IMAP is a mail retrieval protocol, but its mailbox management features lack the features associated with POP mail management" contradicts the rest of the section, which says IMAP lets several clients use one mailbox at once and lets the client manage the mailbox on the server. Key nothing to that sentence. 7.1.6 also spells IMAP "Internet Message Access Protocol"; the objectives and 6.3.6 say "Internet Mail Access Protocol", as the IMAP card (c1-u06-f029) does.
- **7.2.1, NAT:** the first paragraph calls a SOHO router's NAT "port-based or overloaded NAT", then contrasts port-based NAT with "overloaded NAT, also known as PAT" as if they were different. Key nothing to the kinds of NAT.
- **7.1.8, RADIUS and TACACS+:** gives RADIUS as "TCP/UDP 1812/1813" (RADIUS runs over UDP) and says TACACS is "commonly used to authenticate devices such as routers and switches" (TACACS+ authenticates the administrators who manage them). Neither is a Core 1 objective term. Key nothing to their ports or roles; the AAA card (c1-u07-f006) names them only as protocols AAA is run with.
- **7.1.5, figure description:** says the client submits mail "over the secure post 587" and spells SMTP "S M P T" once. Typos only.
